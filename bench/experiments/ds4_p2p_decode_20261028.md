The first decode P2P model screen was mixed: coding +0.05%, async +1.72%, long-context −1.20% versus pooled AR2 controls. All 12 timed requests were free of observed KFD eviction and memory-pressure events. AR2 control drift was 0.74%/2.30%/1.57%, respectively. These short natural-generation requests do not establish a general gain; outputs and MTP work can vary with adaptive cache state. All four coding outputs matched. Frozen-placement numerical checks matched 1,551,360 full-vocabulary values.

The model prototype used the original peer grid and P2P only at 4+ rows, retaining AR2 below that. It reserved equal scratch in controls and candidates and included its synchronization/error-copy overhead. Normal serving was restored with the original executable, environment, context and GPU topology independently verified. These model results are from the optimized serving snapshot, not this branch's current-upstream production binary.

Each run compares original host transport, exact one-launch AR2 and peer with independent rank submitter threads. The order 1/4/2/8/16/1 brackets baseline drift. Per shape: two warmups, 12 balanced repetitions per arm, 64 chained collectives per batch; setup and checks outside events. GPU events include CPU launch gaps. All runs repeat numerical edge cases, changing sizes and sequence wrap, guards, missing-peer 50 ms deadline, and sticky poison/draining checks. The initial whole-process two-CPU affinity sweep distorted small-window controls; those measurements are retained in the JSON, and the unrestricted repeat matches the original operator setup.

The new `PeerAr::work_per_thread` defaults to 1 and accepts 1/2/4/8/16, identically on both ranks. It changes the launch grid only; original rank-order F32 additions and allocated flag/payload capacities remain.
